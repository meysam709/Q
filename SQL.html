SQL Complete Summary

A complete remembrance‑style SQL reference covering DDL, DML, joins, subqueries, aggregation, window functions, CTEs, and more – with clear syntax examples.

1. SQL Basics

SQL (Structured Query Language) is used to communicate with relational databases. It is declarative: you specify *what* you want, not *how* to get it.

Key characteristics

  • Declarative language
  • Works with sets of rows
  • Standardized (ISO/IEC 9075)
  • Many dialects (MySQL, PostgreSQL, SQLite, SQL Server…)

Common uses

  • Data retrieval & reporting
  • Data manipulation (CRUD)
  • Schema definition
  • Analytics & business intelligence

Basic query

SELECT * FROM customers;

5. Data Definition Language (DDL)

CREATE TABLE

CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    salary DECIMAL(10, 2),
    hire_date DATE DEFAULT CURRENT_DATE
);

ALTER TABLE

ALTER TABLE employees ADD COLUMN email VARCHAR(255);
ALTER TABLE employees DROP COLUMN email;

DROP TABLE

DROP TABLE employees;  -- irreversible!

Constraints

PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, CHECK (salary > 0)

7. SELECT & Filtering

SELECT name, salary
FROM employees
WHERE salary > 50000
  AND department_id IN (1, 2, 3)
  AND name LIKE 'A%'
ORDER BY salary DESC;

DISTINCT

SELECT DISTINCT department_id FROM employees;

LIMIT / TOP

SELECT * FROM employees LIMIT 10;           -- PostgreSQL / MySQL
SELECT TOP 10 * FROM employees;       -- SQL Server

8. Joins

INNER JOIN

SELECT e.name, d.department_name
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id;

LEFT JOIN

SELECT e.name, d.department_name
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.id;   -- all employees, even without dept

RIGHT JOIN, FULL OUTER JOIN, CROSS JOIN

Supported by most DBMS. CROSS JOIN returns Cartesian product.

Always use table aliases for clarity and to resolve ambiguous column names.

9. Subqueries

-- scalar subquery
SELECT name, (SELECT MAX(salary) FROM employees) AS max_salary
FROM employees;

-- IN subquery
SELECT name
FROM employees
WHERE dept_id IN (SELECT id FROM departments WHERE budget > 100000);

-- correlated subquery
SELECT e.name, e.salary
FROM employees e
WHERE e.salary > (SELECT AVG(salary) FROM employees WHERE dept_id = e.dept_id);

10. Aggregation & GROUP BY

SELECT department_id,
       COUNT(*) AS num_employees,
       AVG(salary) AS avg_salary,
       MAX(salary) AS max_salary
FROM employees
GROUP BY department_id
HAVING COUNT(*) > 5;
FunctionDescription
COUNT()Number of rows
SUM()Total sum
AVG()Average
MIN() / MAX()Minimum / maximum value
GROUP_CONCAT() / STRING_AGG()Concatenate strings (MySQL / PostgreSQL)
HAVING filters after aggregation, WHERE before.

12. Views

CREATE VIEW high_earners AS
SELECT name, salary
FROM employees
WHERE salary > 100000;

SELECT * FROM high_earners;

DROP VIEW high_earners;
Views are virtual tables that encapsulate complex queries. Some are updatable (depends on DB).

13. Indexes

CREATE INDEX idx_emp_name ON employees(last_name);
CREATE UNIQUE INDEX idx_emp_email ON employees(email);
DROP INDEX idx_emp_name;

Indexes speed up SELECT queries but slow down INSERT/UPDATE/DELETE.

14. Transactions

BEGIN;  -- or START TRANSACTION
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;  -- or ROLLBACK

ACID properties: Atomicity, Consistency, Isolation, Durability.

15. Common Table Expressions (CTEs)

WITH dept_avg AS (
    SELECT dept_id, AVG(salary) AS avg_salary
    FROM employees
    GROUP BY dept_id
)
SELECT e.name, e.salary, d.avg_salary
FROM employees e
JOIN dept_avg d ON e.dept_id = d.dept_id
WHERE e.salary > d.avg_salary;

CTEs improve readability and can be recursive (e.g., for hierarchical data).

16. Window Functions

SELECT name, salary, department_id,
       RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) AS rank,
       AVG(salary) OVER (PARTITION BY department_id) AS dept_avg
FROM employees;
FunctionDescription
ROW_NUMBER()Unique row number within partition
RANK()Rank with gaps on ties
DENSE_RANK()Rank without gaps
SUM() / AVG() OVERRunning totals, moving averages
LAG() / LEAD()Access previous or next row

17. Normalization & Best Practices

Normal Forms

1NF: Atomic values, no repeating groups.
2NF: No partial dependencies.
3NF: No transitive dependencies.

Design tips

  • Use meaningful table & column names
  • Always define a primary key
  • Avoid SELECT * in production
  • Parameterize queries to prevent SQL injection

18. Quick Remember Tips

Order of execution

FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT

NULL handling

NULL means unknown. Use IS NULL, not = NULL. Aggregates ignore NULLs except COUNT(*).

Joins vs subqueries

Joins are usually faster. Correlated subqueries can be very slow.

Index wisely

Create indexes on columns used in WHERE, JOIN, and ORDER BY. Don't over‑index.

Dialect differences

Always check DB‑specific syntax (e.g., LIMIT vs TOP, string concatenation, date functions).

Common pitfalls: forgetting the WHERE clause in UPDATE/DELETE, using commas in FROM (old‑style join), mixing aggregate and non‑aggregate columns without GROUP BY, and not handling NULLs properly.
