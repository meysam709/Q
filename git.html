Git – The Complete Reference

The most comprehensive Git guide you'll ever need. Covers configuration, core workflows, branching, merging, rebasing, remotes, advanced techniques, plumbing, hooks, and troubleshooting – with countless real‑world command examples.

1. Git Fundamentals

Git is a distributed version control system that tracks changes in files and coordinates work among multiple people. It stores snapshots of a mini filesystem, not diffs.

Key concepts

  • Repository: directory with .git
  • Commit: snapshot of tracked files
  • Branch: movable pointer to a commit
  • HEAD: current branch/commit
  • Index (staging area): what will go into next commit

First‑time setup

git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main

2. Creating & Cloning Repos

git init project            # new repo in 'project' folder
git clone https://github.com/user/repo.git
git clone -b branch url       # clone specific branch
git clone --depth 1 url       # shallow clone (latest only)

Checking status & history

git status                    # see what's staged, modified, untracked
git log --oneline --graph --decorate --all  # beautiful history
git diff                      # unstaged changes
git diff --staged             # changes in staging area
git show COMMIT                # inspect a commit

3. Staging, Committing, & Undoing

git add file               # stage single file
git add .                  # stage all changes
git add -u               # stage modifications & deletions (not untracked)
git add -p               # interactively stage hunks

git commit -m "message"    # commit with message
git commit -am "message"   # stage tracked files & commit (skip add)
git commit --amend       # fix last commit (add to it, change msg)

Undoing changes

git restore file           # discard working tree changes
git restore --staged file  # unstage
git reset HEAD file          # older way to unstage
git revert COMMIT          # create new commit that undoes a previous commit

4. Branching & Navigation

Branches are lightweight pointers to commits. Create, switch, merge, and delete branches freely.

git branch                     # list local branches
git branch -a                # list all (local + remote)
git branch feature           # create branch 'feature'
git switch feature           # switch to branch (new command)
git checkout feature        # older way to switch
git switch -c feature      # create and switch in one step
git branch -d feature         # delete merged branch
git branch -D feature         # force delete unmerged branch
Good practice: use short‑lived topic branches and merge them via pull requests.

5. Merging vs. Rebasing

Merge

git merge feature             # merge 'feature' into current branch
git merge --no-ff feature   # create merge commit even if fast‑forward possible

Rebase

Re‑apply commits on top of another base tip. Rewrites history – never rebase public commits.

git rebase main              # rebase current branch onto main
git rebase -i HEAD~3      # interactive rebase last 3 commits (squash, reword…)

Cherry‑pick

git cherry-pick COMMIT   # apply a specific commit to current branch

6. Working with Remotes

git remote -v                    # list remote repositories
git remote add origin url     # add remote named 'origin'
git fetch origin                # download objects/refs from remote (no merge)
git pull                         # fetch + merge (or rebase with --rebase)
git pull --rebase               # fetch + rebase (cleaner history)
git push origin main           # push branch to remote
git push -u origin feature   # set upstream tracking
git push --delete origin feature  # delete remote branch

7. Stashing Changes

git stash                        # save uncommitted changes & revert to HEAD
git stash pop                    # apply most recent stash & remove it
git stash apply stash@{2}    # apply specific stash without dropping
git stash list                    # list stashes
git stash drop stash@{0}      # delete a stash
Stashing is perfect when you need to switch branches quickly but aren't ready to commit.

8. Tags & Releases

git tag v1.0.0                   # lightweight tag
git tag -a v1.0.0 -m "Release 1.0.0"   # annotated tag
git push origin --tags        # push all tags
git push origin v1.0.0       # push single tag

9. Advanced Git Commands & Techniques

Bisect

git bisect start
git bisect bad             # current commit is bad
git bisect good v1.0   # known good commit
# Git checks out midpoint; test & mark good/bad until culprit found

Reflog

git reflog                 # show log of HEAD movements (undo lost commits)
git reset --hard HEAD@{1}  # go back to previous HEAD (careful!)

Submodules

git submodule add url path
git submodule update --init --recursive

Worktrees

git worktree add ../hotfix main   # check out branch in separate folder

10. Git Hooks

Scripts that run automatically on certain events. Located in .git/hooks/ (rename sample files removing .sample).

Common hooks

  • pre‑commit: before commit msg, can lint/format
  • commit‑msg: validate commit message pattern
  • pre‑push: run tests before pushing
  • post‑receive: server‑side, after push (deploy)
# Example pre-commit hook (bash)
#!/bin/sh
if grep -r "TODO" . --exclude-dir=.git; then
    echo "Found TODO – please remove before committing"
    exit 1
fi

11. Git Internals (Plumbing Commands)

Git stores data as objects: blobs (file content), trees (directory listing), commits (snapshot), tags.

git cat-file -p COMMIT        # inspect commit object
git ls-tree TREE_SHA           # list tree contents
git count-objects                # see object statistics
git gc                          # garbage collection, optimize repo

Objects are content‑addressed by SHA‑1 hash. The .git/objects directory stores them.

13. Common Git Workflows

GitHub Flow

  • Feature branch → open PR → review → merge → delete branch
  • Simple, perfect for continuous deployment

Git Flow

  • Long‑lived branches: main, develop
  • Feature branches, release branches, hotfix branches
  • More complex, suited for scheduled releases

Trunk‑Based Development

  • Direct commits to main, short‑lived branches
  • Feature flags, high discipline, fast feedback

14. Troubleshooting & Recovery

Lost commits

git reflog                 # find the lost commit
git checkout COMMIT       # inspect it
git branch recover COMMIT # create a branch at that commit

Undo a bad merge

git reset --hard HEAD~1    # if merge not yet pushed
git revert -m 1 MERGE_COMMIT  # if already pushed

Remove sensitive data

git filter-branch --force --index-filter \
 'git rm --cached --ignore-unmatch secret.txt' --prune-empty -- --all

18. Final Tips & Best Practices

Commit messages

  • Imperative mood ("Add feature" not "Added")
  • Limit subject line to 50 chars
  • Separate subject from body with blank line
  • Explain what & why, not how

Branch hygiene

  • Delete merged branches
  • Keep branches focused (one feature/bug per branch)
  • Regularly fetch/pull to stay updated
Common pitfalls: committing sensitive data, force pushing to shared branches, amending public commits, using git add . blindly, and not setting up a proper .gitignore.
